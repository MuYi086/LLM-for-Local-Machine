# 四个 Index 模型 Demo 的依赖补全说明

本文依据当前四个 `demo.py`、仓库配置和官方模型/代码说明整理，核对日期为
2026-10-11。模型权重、外部源码和运行环境请放在仓库外，避免把大文件或第三方源码提交进仓库。

这四个 Demo 的输出类型不同：Echo 直接调用 Index-Echo-S2ST 原生 API 生成 WAV；
Homura、Nailong、Index-Translate 调用各自的官方文本推理脚本，并原样保存 TXT。
它们不调用本仓库的 Confucius4-TTS 编排路由。
除模型下载命令外，以下仓库内 `python tests/...` 命令均从仓库根目录执行。

## 1. Index-Echo-S2ST

### Demo 使用方式与当前缺失项

- 入口：`tests/testIndexEchoS2ST/demo.py`。
- 默认输入：`tests/testIndexTranslate/speech.wav`；默认目标语言为英语。
- 输出：`tests/testIndexEchoS2ST/dist/index_echo_s2st_zh_to_en.wav`。
- Demo 导入模型目录里的 `modeling_dubbing.py`，调用 `DubbingBridgeModel.from_pretrained()` 和
  `model.dub()`。因此需要完整原生模型包，只有 `Index-Echo-S2ST-9B.Q8_0.gguf` 不够用；GGUF
  是本仓库服务使用的文本主干，不包含这个 Demo 所需的完整配音 API 和组件。
- 当前环境已发现 Echo GGUF，但未发现完整原生模型目录。官方卡要求单张 GPU 至少 24 GB 显存；
  本机检查到的 RTX 4070 Ti SUPER 为 16 GB，达不到该要求。需要更大显存的 GPU 才能按官方支持方式运行。

### 下载完整模型包

官方来源：[Index-Echo-S2ST-9B 模型卡](https://huggingface.co/IndexTeam/Index-Echo-S2ST-9B)。
模型包包含 `modeling_dubbing.py`、STLM、Hidden2CV mapper、CosyVoice3 及推理代码，下载量较大，
请预留数十 GB 空间。

```bash
python -m pip install --upgrade huggingface_hub

export HF_MIRROR_DIR="${HF_MIRROR_DIR:-$HOME/hf-mirror}"
hf download IndexTeam/Index-Echo-S2ST-9B \
  --local-dir "$HF_MIRROR_DIR/IndexTeam/Index-Echo-S2ST-9B"

export INDEX_ECHO_S2ST_NATIVE_MODEL_DIR="$HF_MIRROR_DIR/IndexTeam/Index-Echo-S2ST-9B"
```

下载完成后应能找到：

```text
$INDEX_ECHO_S2ST_NATIVE_MODEL_DIR/modeling_dubbing.py
```

如果模型已放在其他目录，只需把 `INDEX_ECHO_S2ST_NATIVE_MODEL_DIR` 设为包含该文件的目录。

### 建立 Echo Python 环境

官方模型卡列出的测试版本如下。`torch` 和 `torchaudio` 的 `+cu129` wheel 必须来自提供 CUDA 12.9
构建的 PyTorch wheel 源；先按 [PyTorch 安装选择器](https://pytorch.org/get-started/locally/)确认与
驱动匹配的 CUDA wheel。模型卡的完整依赖锁定为：

```bash
python3.12 -m venv "$HOME/.venvs/index-echo-s2st"
source "$HOME/.venvs/index-echo-s2st/bin/activate"
python -m pip install --upgrade pip

# 下列两项需要能提供 cu129 wheel 的 PyTorch 源；如镜像不含该构建，按上面的官方选择器调整源。
python -m pip install \
  --extra-index-url https://download.pytorch.org/whl/cu129 \
  torch==2.11.0+cu129 torchaudio==2.11.0+cu129

python -m pip install \
  transformers==5.6.0 tokenizers==0.22.2 librosa==1.0.0 \
  onnxruntime==1.30.0 wetext==0.0.4 kaldifst==1.8.0 \
  conformer==0.3.2 hydra-core==1.3.7 HyperPyYAML==1.2.3 \
  lightning==2.6.6 x-transformers==2.11.24 einx==0.4.3 \
  frozendict==2.4.7 pyworld==0.3.5 soundfile==0.13.1 \
  modelscope==1.37.1 safetensors==0.7.0 numpy==2.4.6 \
  openai-whisper==20250625
```

系统还需要 FFmpeg 可执行文件在 `PATH` 中。Ubuntu/Debian 可通过系统包管理器安装：

```bash
sudo apt-get update
sudo apt-get install -y ffmpeg
ffmpeg -version
```

模型卡指出 `openai-whisper` 仅用于 ASR 评估/自检；日文前端 `pyopenjtalk`、`pykakasi` 已随模型包
提供。Echo 自带的 CosyVoice3 属于 Index-Echo 原生模型包的一部分，不是 Confucius4-TTS。

### 运行

在 Echo 虚拟环境中运行，且使用满足官方显存要求的 GPU：

```bash
export HF_MIRROR_DIR="${HF_MIRROR_DIR:-$HOME/hf-mirror}"
export INDEX_ECHO_S2ST_NATIVE_MODEL_DIR="$HF_MIRROR_DIR/IndexTeam/Index-Echo-S2ST-9B"
export INDEX_ECHO_S2ST_DEVICE=cuda
python tests/testIndexEchoS2ST/demo.py
```

## 2. Index-Homura

### Demo 使用方式与当前缺失项

- 入口：`tests/testIndexHomura/demo.py`；调用上游 `inference/llm/syllable_translate.py`。
- 模型 ID：`IndexTeam/Index-Homura-9B`；Demo 请求目标语言 `en`、目标音节数 `36`。
- 输出：`tests/testIndexHomura/dist/index_homura_zh_to_en.txt`，内容是官方脚本的原始标准输出。
- 当前缺少官方 `Index-Translate` 源码目录、Python 包 `openai`，以及可用的文本模型 API。
  默认 API 地址 `http://127.0.0.1:8000/v1` 当前未监听。
- 本机已有 Q8_0 GGUF：`$HF_MIRROR_DIR/IndexTeam/Index-Homura-9B-GGUF/Index-Homura-9B.Q8_0.gguf`；
  若该文件仍在，无需再次下载。它需要由支持该 GGUF 的 `llama-server` 或其他兼容服务器加载。

### 三个文本 Demo 共用的源码、客户端与服务端依赖

官方源码：[bilibili/Index-Translate](https://github.com/bilibili/Index-Translate)，脚本说明见
[文本推理 README](https://github.com/bilibili/Index-Translate/blob/main/inference/llm/README.md)。
在仓库根目录执行下面的 clone 命令时，源码会放在本仓库的同级目录，符合 Demo 默认查找位置；
第三方源码不要放进本仓库提交。

```bash
# 从仓库根目录执行；如果网络不能访问 GitHub，可先在可联网机器下载 ZIP，再解压到 ../Index-Translate。
git clone --depth 1 https://github.com/bilibili/Index-Translate.git ../Index-Translate

python3.12 -m venv "$HOME/.venvs/index-translate-client"
source "$HOME/.venvs/index-translate-client/bin/activate"
python -m pip install --upgrade pip
python -m pip install openai httpx

export INDEX_TRANSLATE_SOURCE_DIR="$(realpath ../Index-Translate)"
export INDEX_TRANSLATE_PYTHON="$HOME/.venvs/index-translate-client/bin/python"
export HF_MIRROR_DIR="${HF_MIRROR_DIR:-$HOME/hf-mirror}"
```

官方 CLI 使用 `openai`、`httpx` 客户端；这里只安装客户端依赖。模型服务必须单独运行，并实际加载
对应的 9B 家族模型。若选择官方 vLLM 服务，按上游 README 安装带 Qwen3.5 支持的 vLLM 和
`inference/llm/requirements.txt`；官方 9B BF16 服务估算约需 24 GB 显存，尚未计入长上下文 KV cache。
本机现有 Q8_0 GGUF 可由 llama.cpp 服务加载，因此下面按该文件配置。

本机没有 `llama-server`。可从 [llama.cpp Releases](https://github.com/ggml-org/llama.cpp/releases)
下载与 Linux x86_64、NVIDIA/CUDA 环境匹配的官方预编译包；或从
[llama.cpp 官方仓库](https://github.com/ggml-org/llama.cpp)构建。CUDA 构建需要 CUDA Toolkit、CMake、
C++ 编译器：

```bash
git clone --depth 1 https://github.com/ggml-org/llama.cpp.git ../llama.cpp
cmake -S ../llama.cpp -B ../llama.cpp/build -DGGML_CUDA=ON
cmake --build ../llama.cpp/build --config Release --target llama-server -j 8
export LLAMA_SERVER="$PWD/../llama.cpp/build/bin/llama-server"
"$LLAMA_SERVER" --version
```

需要一个模型 API 服务监听 `127.0.0.1:8000`，供官方脚本通过 OpenAI-compatible
`/v1/chat/completions` 调用。为避免显存叠加，三个模型应逐个启动、逐个运行 Demo；每次先停止上一个
`llama-server`，再用下一节对应的模型文件和 alias 启动。各本地 GGUF 模型卡提供 llama.cpp 用法，
llama.cpp 服务端说明见 [llama-server README](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)。

### 下载 Homura GGUF（仅当本机文件缺失时）

官方来源：[Index-Homura-9B-GGUF](https://huggingface.co/IndexTeam/Index-Homura-9B-GGUF)。
以下命令只下载当前 Demo 所需的 Q8_0 模型文件：

```bash
python -m pip install --upgrade huggingface_hub
export HF_MIRROR_DIR="${HF_MIRROR_DIR:-$HOME/hf-mirror}"
hf download IndexTeam/Index-Homura-9B-GGUF Index-Homura-9B.Q8_0.gguf \
  --local-dir "$HF_MIRROR_DIR/IndexTeam/Index-Homura-9B-GGUF"
```

### 配置并运行

终端 A 启动 Homura GGUF 服务：

```bash
export HF_MIRROR_DIR="${HF_MIRROR_DIR:-$HOME/hf-mirror}"
export LLAMA_SERVER="${LLAMA_SERVER:-$PWD/../llama.cpp/build/bin/llama-server}"
"$LLAMA_SERVER" \
  -m "$HF_MIRROR_DIR/IndexTeam/Index-Homura-9B-GGUF/Index-Homura-9B.Q8_0.gguf" \
  --alias IndexTeam/Index-Homura-9B \
  --host 127.0.0.1 --port 8000 --ctx-size 4096 --n-gpu-layers 99 \
  --chat-template-kwargs '{"enable_thinking":false}'
```

终端 B 使用文本客户端环境运行：

```bash
source "$HOME/.venvs/index-translate-client/bin/activate"
export INDEX_TRANSLATE_SOURCE_DIR="$(realpath ../Index-Translate)"
export INDEX_TRANSLATE_PYTHON="$HOME/.venvs/index-translate-client/bin/python"
export INDEX_HOMURA_API_BASE_URL=http://127.0.0.1:8000/v1
export INDEX_HOMURA_API_KEY=EMPTY
python tests/testIndexHomura/demo.py
```

`--ctx-size 4096` 足以覆盖当前短字幕 Demo；若以后把输入换成长文本，需要按显存情况增大上下文。

## 共同检查项

1. 源码目录应含 `inference/llm/translate.py`、`syllable_translate.py` 和 `doc_translate.py`。
2. 文本环境应能执行 `python -c 'import openai, httpx'`。
3. 当前对应的 `llama-server` 应能执行 `curl -fsS http://127.0.0.1:8000/health`。
4. `INDEX_HOMURA_API_BASE_URL`、`INDEX_NAILONG_API_BASE_URL` 或 `INDEX_TRANSLATE_API_BASE_URL`
   指向本次启动的模型服务 `/v1` 地址；本地服务的 API key 设为 `EMPTY`。
5. 每次只启动一个 9B Q8_0 服务，然后执行它的 demo；停止服务后再切换下一个模型。
6. 本仓库当前 8382–8385 端口是完整语音翻译路由，会串接 ASR/TTS。它们不是这些文本 Demo 的
   OpenAI-compatible 文本 API，不能作为上述 `*_API_BASE_URL`。
