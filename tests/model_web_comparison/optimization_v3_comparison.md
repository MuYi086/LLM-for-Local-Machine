# 第三版：Ornith MTP 完整网页复测

本轮保留原 Q5 主模型、mmproj、32K 上下文、batch 512、单并发、共享 GPU 锁和 sleep-idle 生命周期。
提示词 SHA-256：`67ed0ec8d791e654a821cc9b210fd63c6dfbbe9d997e23a8a50017e446ec896c`。三次完整测试均为 temperature=0、top_p=1、max_tokens=8192、关闭 thinking、流式响应和 0.25 秒资源采样；每次 Ornith → Qwen 串行。

历史各版本为一次完整任务，本轮为三次；表中 v3 为中位数。历史与本轮并非交错 A/B，环境缓存和后台负载有差异，不能把所有波动解释为参数收益。

GPU 总量包含桌面等后台使用量；RSS 及系统内存增量是不同口径。Ornith 多放 CPU 专家使内存占用上升，换取独立 MTP 的显存空间。16 GiB 卡仍只有约 0.7–0.9 GiB 余量，因此未采用再少一层 CPU 专家的激进分配；未缩短上下文。此次峰值来自这份约 7K 输出的任务，不是 32K 满上下文压力测试。

## 网页质量

三次两款模型的原始内联 JavaScript 均通过 Node 语法检查。另对第三次原始页面在 Chromium 离线模式做浏览器冒烟测试，未修改模型输出；检查范围不等于全面的交互或无障碍验证。

- ornith_1_5_35b_a3b：浏览器运行时错误 0；目的地输入=True，预算即时更新=True，勾选=True，行李勾选=True，添加行程=True，删除行程=False。
- qwen3_6_35b_a3b：浏览器运行时错误 0；目的地输入=False，预算即时更新=True，勾选=True，行李勾选=False，添加行程=True，删除行程=True。

浏览器实测：Ornith 点击删除后行程数保持 7 不变，源码删除回调引用循环结束后的 `i`，导致删除失效。Qwen 没有目的地输入框；行李勾选后重新渲染没有将 `item.checked` 绑定到新 checkbox，导致原生勾选状态未保留（准备数量及样式仍会变化）。这些功能问题不能由 JavaScript 语法检查发现。

模型输出的功能缺陷保留在原始页面及预览中；推理加速不保证网页功能质量改善。

## 启动与验证

用户确认后，已将最终实测配置直接提升为 `bash start.sh` 默认值，无需实验包装脚本；环境变量仍可覆盖。完整复测步骤见 [测试说明](README.md)。旧分阶段包装脚本已删除。
默认配置提升后，无模型完整质量门禁通过（68 项根测试和16项 Ornith 测试），包括14项启动合同测试；新增测试核对无环境覆盖时的全部关键参数，原有测试继续覆盖显式环境覆盖。日志为运行目录的 `defaults_quality_gate.log`。Shell 语法和 diff 检查通过；代码审查修复了无条件加载 MTP 与历史显存配置的冲突。
全部正式请求均以 stop 结束，没有输出截断；两款模型各自的三次 HTML SHA-256 完全一致，Qwen 还与 v2 逐字一致。后端正式日志的速度与客户端统计相符，Ornith MTP 接受率 73.811%、平均长度 3.95；Qwen 接受率 82.325%、平均长度 4.29。接受率仅作诊断，不作为选型目标。

所有阶段已正常停止服务并确认两个 backend PID 退出，无遗留 quarantine；恢复测试前无服务运行的状态。
