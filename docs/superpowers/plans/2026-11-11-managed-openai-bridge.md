# 将本地兼容网关纳入统一启动

用户要求：`bash start.sh` 一并启动供 OpenCode 使用的网关，Ctrl+C 一并退出。
沿用现有 `easel_bridge`、Bearer Key、loopback 绑定和上游 GPU 锁，不启动 OpenCode 客户端。

实施顺序：
1. 先补充无模型回归：缺失/弱 Key 阻止启动；配置文件加载；真实网关 `/v1/models`；
   SIGINT 与网关退出均使整个测试进程栈收尾，释放端口与 backend PID 文件。
2. `start.sh` 读取 `.env.easel-bridge`，校验 Key 和端口，将网关加入端口检查、setsid、wait 和 cleanup。
3. 更新运行文档与服务数量；在本机将现有 OpenCode 的环境变量 Key 引用改为权限 0600 的独立文件引用，
   避免新终端重复加载环境。只调整用户配置，不把密钥写入仓库。
4. 执行 Bash 语法检查、启动回归、完整无模型质量门禁；不重启用户正在使用的真实模型栈。

验证重点：未泄露 Key；8500 固定 loopback；启动失败发生在真实模型之前；信号清理与网关退出监控；
保留现有工作区变更。无需依赖变化，不创建提交。

完成记录：启动脚本与文档已更新；本机 OpenCode 已改用 0600 Key 文件引用，并在清除 Key 环境变量后成功列出 local-qwen 模型。
完整质量门禁通过：Ruff 检查/格式、4 个项目 lock 校验、renderer 核心测试、能力清单、135 项主测试与 17 项 Ornith 测试。
端口联动测试先观察到缺失上游环境，再补默认 URL 后在完整门禁通过。未重启真实模型栈。

退出回归补充：用户再次发现旧服务残留后，确认主启动脚本已经消失。原测试只发送主进程 SIGINT，
漏测了终端进程组信号。扩展测试在原实现复现 SIGINT/SIGHUP 后端口仍被占用；修复日志进程信号处理、
cleanup 的 SIGPIPE/重复信号保护和失效日志管道回退后，六种退出触发均通过。已通过 shutdown 入口清理真实遗留进程。

信号修复后完整质量门禁再次通过：135 + 17 项测试；最终确认真实 17 个端口可绑定、GPU 锁空闲且无 quarantine。
