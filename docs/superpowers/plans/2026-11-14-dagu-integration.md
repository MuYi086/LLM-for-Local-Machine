# Dagu Integration Implementation Plan

**Goal:** 提供独立的 Dagu 排队入口，调用现有 VoxCPM2 和 MOSS API。

**Architecture:** Dagu 独立于 start.sh，使用共享 GPU 队列；任务脚本消费仓库外的 JSON 输入，通过现有 HTTP API 推理，独占创建任务目录并发布产物。遇到不确定状态不自动重试。

**Tech Stack:** Dagu YAML、Python 标准库、unittest。

## 约束与验证

- 不修改现有模型 API、GPU 锁和 start.sh；Dagu 不自行获取 GPU 锁。
- 模型请求提交前独占创建任务目录；重复任务禁止再次提交。
- HTTP 错误、超时、非法响应和意外中断不得发布成功产物或自动重试。
- 测试通过本机假 HTTP 服务验证请求、产物、重复任务和故障；不加载模型。
- 单独验证固定版本 Dagu 的配置与 DAG 解析，并运行仓库质量门禁。
