# Ornith-1.5-35B-A3B Implementation Plan

**Goal:** Serve Ornith using CUDA with the first 20 MoE expert layers on CPU, under the repository's shared GPU lease and quarantine contract, and generate one real sample.

**Architecture:** A FastAPI adapter listens on 8401 and forwards to a loopback llama-server on 8402. The server loads the GGUF and vision mmproj, uses CUDA layers plus CPU MoE experts, and sleeps after each request. The adapter holds `GPU_LOCK_FILE` until `/props` confirms `is_sleeping`, then waits `CUDA_RELEASE_DELAY` and clears its request marker. Startup uses the same lease and marker, waiting for the initial model load to finish and unload before other GPU services start.

**Tech Stack:** Python 3.12.13, FastAPI, HTTPX, llama.cpp `llama-server`, Bash, unittest.

**Spec:** `docs/superpowers/specs/2026-11-09-ornith-1-5-35b-a3b-design.md`

## Global Constraints

- Model files and llama.cpp source/build remain outside the repository.
- The GGUF and mmproj are read-only and default to `$HF_MIRROR_DIR/AtomicChat/Ornith-1.5-35B-A3B/`.
- Public API listens on 8401; llama-server binds only `127.0.0.1:8402`.
- Default hybrid settings: `--device CUDA0`, `--gpu-layers 99`, `--n-cpu-moe 20`, `--flash-attn on`, `--jinja`, context 32768, parallel 1, and sleep-idle 1 second.
- Every model request uses the shared positive-timeout GPU lock. Quarantine remains if sleep/unload cannot be confirmed.
- Sample outputs go under `storage/`, not source control.

## Review Focus

- Confirm preflight happens before lock acquisition and no other service starts before initial model sleep is confirmed.
- Confirm each request checks `/props.is_sleeping` before sending the generation request, avoiding a request arriving during sleep transition.
- Confirm the `.quarantine` marker spans inference and model unload, and survives failure to confirm sleep.
- Confirm stream cleanup holds the lock through upstream closure and sleep confirmation.
- Confirm startup exec gate writes process identity before model loading begins, so recovery never sees an untracked backend.
- Confirm recovery checks the recorded backend process group and loopback API before removing the marker.
- Exercise real CUDA capability and an actual model request, not just mocked adapter tests.
