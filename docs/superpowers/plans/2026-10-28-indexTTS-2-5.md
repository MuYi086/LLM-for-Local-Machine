# IndexTTS-2.5 HTTP Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add IndexTTS-2.5 voice cloning at port 8323 and `POST /v1/index-team/indexTTS-2.5`.

**Architecture:** A lightweight FastAPI service validates requests and audio references, serializes GPU access, and launches one temporary worker. The worker imports the pinned upstream source outside the repository and calls `IndexTTS2.infer`; a temporary read-only symlink view combines the local checkpoint and auxiliary models.

**Tech Stack:** Python 3.12.13, uv, FastAPI, Pydantic, `llm_local_runtime`, PyTorch/TorchAudio, official IndexTTS-2.5 source.

**Spec:** `docs/superpowers/specs/2026-10-28-indexTTS-2-5-design.md`; user request: `task1.md`.

## Global Constraints

- Deployment uses Linux and Python `3.12.13`.
- Each model service uses its own uv project and one-shot worker.
- HTTP processes must not import Torch or model packages.
- Heavy requests use the shared GPU lock; default lock wait is 900 seconds and must remain positive.
- Model source files are read-only; worker artifacts and generated WAVs use runtime/storage directories.
- Model requests run offline and must fail preflight if required local assets or source code are absent.
- Add no model weights or third-party source to the repository.

## Review Focus

- Missing checkpoint, auxiliary model, or source file returns unavailable before taking the GPU lock; covered by resource-readiness tests.
- Invalid or unknown logical reference audio returns 404 without reading arbitrary paths; covered by the route test.
- Unsupported language, invalid emotion vector, or out-of-range duration factor returns 422; covered by request validation tests.
- Worker timeout/nonzero exit cleans its process group and temporary files; covered by worker-manager lifecycle tests.
- GPU queue timeout returns 503 without starting a worker; covered by the route test.

**Interfaces:**
- `POST /v1/upload_audio` accepts multipart `audio`, `full_path`, optional `prompt_text` and commits through `AudioReferenceStore`.
- `GET /v1/check/audio?file_name=...` checks a logical audio reference.
- `GET /v1/health` reports checkpoint, external source, auxiliary assets, worker, Python packages, and CUDA readiness without loading Torch.
- `POST /v1/index-team/indexTTS-2.5` accepts JSON `text`, `audio_path`, `lang`, optional `duration_factor`, `emo_vector`, `emo_alpha`; success returns and atomically persists `audio/wav`.
- `IndexTTS25WorkerManager.build_worker_payload(request) -> dict[str, Any]` resolves the logical reference and complete model view before GPU queuing; `run_worker(payload) -> bytes` starts/cleans one process group with a 900-second default timeout.
