# Ornith-1.5-9B-GGUF Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the mirrored Ornith-1.5-9B-Q8_0 GGUF through a guarded API on port 8503 at `/v1/ornith-ai/Ornith-1.5-9B-GGUF`, launched and shut down by `start.sh`, with a real-call demo under `tests/`.

**Architecture:** Add a dedicated 9B adapter that reuses the model-neutral `llama_cpp_runtime` API and lifecycle runtime. Run its llama-server on loopback port 8504, share `GPU_LOCK_FILE` with all other GPU providers, and use sleep-idle/quarantine handling for request and startup/shutdown safety.

**Tech Stack:** Python 3.12, FastAPI, HTTPX, uvicorn, llama.cpp `llama-server`, Bash, unittest.

**Spec:** `task10.md` and repository `AGENTS.md`.

## Global Constraints

- Source GGUF remains outside the repository and is read-only.
- Public API binds using `HOST` defaults; llama-server binds only to `127.0.0.1`.
- All inference uses the shared `GPU_LOCK_FILE`; a quarantine marker prevents inference.
- Startup and shutdown must verify backend sleep-idle or confirmed process-group/API exit.
- Do not add Python dependencies or run real-model inference in the no-model quality gate.
- Keep the real-call demo output under `storage/llm_tests/` and never overwrite an existing sample.

## Review Focus

- Missing/empty GGUF must fail startup before service launch; cover in `tests/test_start_services.py`.
- API and backend ports must both be checked; cover in `tests/test_start_services.py`.
- The API must force the 9B model alias and exact route; cover adapter contract tests.
- Backend must stay loopback-only and share the GPU lock; cover startup command assertions.
- The demo must reject malformed/empty model responses and preserve existing outputs; cover demo tests.
