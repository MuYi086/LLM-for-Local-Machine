# Qwen3.6-35B-A3B-MTP 接入设计

## 意图

按 `task4.md` 将本机 Qwen3.6-35B-A3B-UD-Q5_K_M GGUF 接入统一 `start.sh` 生命周期，通过 `POST /v1/qwen/Qwen3.6-35B-A3B-MTP` 在 8402 提供 OpenAI Chat Completions 兼容接口，并在测试目录提供真实样例生成器。

## 当前状态与约束

- 权重目录 `$HF_MIRROR_DIR/unsloth/Qwen3.6-35B-A3B-MTP/` 当前含一个 27.1 GB GGUF；metadata 为 `qwen35moe`，40 个主干层加一个 MTP block、256 个专家、每 token 8 个激活专家，无 mmproj。
- 本机 CUDA llama.cpp 已实现 `qwen35moe` 和 `draft-mtp`。真实探针用 32K 上下文、20 个 CPU MoE 层时峰值约 16,018 MiB；25 层时峰值约 13,751 MiB，并以 MTP 模式成功生成文本。因此默认 CPU MoE 设为 25，保留更多显存余量。
- task4 固定 Qwen API 端口 8402；task20 的 Ornith API 保持 8401。LocalAI 当前绑定 `127.0.0.1:8400`。为满足 llama.cpp 使用 8400 且保留 LocalAI，Qwen backend 绑定 `127.0.0.2:8400`；此 loopback 地址已验证可在 LocalAI 继续占用 `127.0.0.1:8400` 时独立绑定。Ornith backend 移到 `127.0.0.1:8403`。
- Qwen 与 Ornith 共享 `GPU_LOCK_FILE` 和 quarantine；两个 llama-server 后端串行预热、每个 API 请求结束后等待 sleep-idle 确认，关闭时分别确认进程组和端口退出。
- 模型权重、llama.cpp 源码/二进制和运行样例均不进入版本控制；Qwen 样例写入 `storage/llm_tests/qwen3_6_35b_a3b/`。

## 目标与非目标

目标是以 Qwen 专属固定路由和 alias 调用本地权重，使用 CUDA0 加速并将前 25 层 MoE 专家放 CPU；启用内置 MTP head，默认 32K 上下文、单并发和 sleep-idle。所有推理遵循共享 GPU 排队、原子 quarantine 标记和失败时 fail-closed 约束。

本次不迁移 LocalAI 端口，不下载权重，不增加模型下载依赖，不添加未提供的视觉 projector，也不修改 audio.cpp 候选或接口。

## 实现方案

### 方案 A：独立单模型 backend（采用）

Ornith 和 Qwen 各保留一个 loopback llama-server 与一个公开适配器。Ornith backend 默认端口改为 8403；Qwen API 为 8402，Qwen backend 为 `127.0.0.2:8400`。通过参数化现有适配器和运行时生命周期函数复用相同 HTTP、GPU 锁和 quarantine 合同；两个 backend 在统一启动脚本中顺序预热，并在关闭时逐一确认停止。

优点是延续已验证的单模型 `/props` 与进程恢复路径，端口职责清楚。代价是同时维护两个睡眠状态的 llama-server 进程及两份启动/关闭配置。

### 方案 B：单 llama.cpp Router

用一个 router backend 和两个模型 preset，通过 alias 动态加载并设置最多一个模型驻留。它减少 backend 进程数量，但需要改写适配器的模型状态探测、启动预热、路由和 quarantine 生命周期，改动范围大于本任务所需。

## 行为细节

- Qwen 适配器固定写入 alias `Qwen3.6-35B-A3B-MTP`，将 client request 转发至 `127.0.0.2:8400/v1/chat/completions`，并在请求前确认 backend sleeping。
- llama-server 使用 `--device CUDA0 --gpu-layers 99 --n-cpu-moe 25 --spec-type draft-mtp --flash-attn on --jinja --ctx-size 32768 --parallel 1 --sleep-idle-seconds 1`。本地 GGUF 已包含 MTP tensors，不另设 draft 文件。
- 样例生成脚本对固定 Qwen 路由提交简体中文 prompt，设置 `chat_template_kwargs.enable_thinking=false` 以避免短输出只返回 reasoning 而无 assistant content；用户 API 请求仍保留自己的 thinking 设置。
- `start.sh` 先验证两个权重文件、CUDA 与必需参数，再通过同一 GPU 锁顺序预热两个 backend，全部 readiness 成功后才启动公开 API。任一 backend 或服务异常都走统一 cleanup。

## 验收

- 无模型测试覆盖两个固定路由、model alias、流式与非流式转发、共享锁与 quarantine，以及 launcher 对 API/backend 端口、CPU MoE、MTP flags、启动顺序和部分启动失败的处理。
- `bash -n start.sh`、`bash scripts/quality_gate.sh` 和完整 unittest 通过。
- 使用真实 Qwen 权重经 `start.sh` 在 8402 请求固定路由，生成非空样例；确认 backend sleeping、GPU quarantine 已清除、两个 llama-server 进程组及端口按 Ctrl+C 完整关闭，且 LocalAI 8400 保持可用。
